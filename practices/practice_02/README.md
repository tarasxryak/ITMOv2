# Практика 2. Дорабатываем SDLC-артефакты с помощью шести техник

**Формат:** обсуждение в тех же командах, 90 минут. Каждый студент работает в своём форке и сдаёт отдельный PR. Работу проверяют ревьюеры курса.

**Вход:** заполненные файлы Практики 1.

**Результат:** шесть воспроизводимых экспериментов и конкретные изменения в SDLC-артефактах.

## Как работать

Работайте в OpenCode в режиме **Build**. Агент сам изменяет `prompts.md`, шесть `experiment.md` и связанные файлы Практики 1. Вы выбираете проблему, формулируете запросы, обсуждаете результаты и проверяете diff.

```text
Помоги выполнить Практику 2 по этому README. Будем последовательно
применять шесть техник к выбранному артефакту. После каждого эксперимента
запиши запрос и фактический результат в experiment.md, внеси согласованную
правку в файл Практики 1 и обнови prompts.md. Покажи diff и проверку.
Мою оценку и причины отказа записывай только из нашего диалога.
```

Команды Git и проверки ниже также выполняет OpenCode по вашему запросу. Перед commit проверьте diff, перед открытием PR — репозиторий и базовую ветку.

## Ветка для второй практики

Продолжайте в своём форке из Практики 1. Если ещё не сделали форк, сначала выполните [подготовку к Практике 1](../practice_01/README.md#до-начала): форк, клонирование, ветка `practice_01` и PR `practice_01 → main` внутри своего форка. Вторая практика использует результаты первой.

Проверьте `git remote -v`: `origin` должен указывать на ваш форк. Создайте ветку `practice_02` в зависимости от состояния первого PR.

### Первый PR уже влит в main

```bash
git switch main
git pull --ff-only origin main
git switch -c practice_02
```

При сдаче откройте PR `practice_02 → main` в своём форке.

### Ревью первой практики ещё идёт

Создайте вторую ветку от первой, сохранив и закоммитив работу по Практике 1:

```bash
git switch practice_01
git switch -c practice_02
```

При сдаче откройте PR **из `practice_02` в `practice_01`** в своём форке. Тогда ревьюер увидит только изменения второй практики. Первый PR остаётся открытым отдельно.

| Работа | base repository | base | head repository | compare |
|---|---|---|---|---|
| Практика 1 | ваш форк | `main` | ваш форк | `practice_01` |
| Практика 2, первая ещё на ревью | ваш форк | `practice_01` | ваш форк | `practice_02` |
| Практика 2, первая уже влита | ваш форк | `main` | ваш форк | `practice_02` |

Не открывайте эти PR в исходный репозиторий курса.

Исправления по ревью первой практики вносите в `practice_01`, затем переносите во вторую ветку:

```bash
git switch practice_02
git merge practice_01
git push origin practice_02
```

После слияния первого PR обновите `main` и включите его изменения во вторую ветку:

```bash
git switch main
git pull --ff-only origin main
git switch practice_02
git merge main
git push origin practice_02
```

Если Git сообщит о конфликтах, поручите OpenCode разрешить их, проверьте diff и завершите merge перед push. Измените `base` второго PR на `main` своего форка и проверьте вкладку **Files changed**: там должны остаться только изменения второй практики. Ветку `practice_01` удаляйте после смены базы второго PR.

## Маршрут занятия

### 0–10 минут. Выберите слабый артефакт

Откройте файлы Практики 1 и выберите один артефакт, которому доверяете меньше всего. Сообщите выбор и проблему OpenCode, чтобы он записал их в `prompts.md`.

### 10–46 минут. Шесть экспериментов

На каждый эксперимент — 6 минут:

1. сформулируйте запрос в OpenCode с использованием нужной техники;
2. поручите агенту выполнить задачу и записать вход, запрос и результат в `experiment.md`;
3. обсудите результат и сообщите, что принимаете или отклоняете;
4. поручите агенту внести согласованные изменения в файл Практики 1;
5. попросите его выполнить проверку и записать итог и вашу оценку.

### 46–65 минут. Сведите изменения

Поручите OpenCode обновить `prompts.md`. Проверьте, что в каждой строке есть конкретное изменение и ссылка на файл и раздел Практики 1.

### 65–80 минут. Проверьте изменения

Проверьте свои артефакты:

- понятны ли требования без дополнительных пояснений;
- есть ли способ проверить каждое требование;
- указаны ли источники утверждений и существенные риски.

### 80–90 минут. Исправьте артефакты

Передайте найденные ошибки OpenCode. Агент исправляет файлы и записывает результаты проверок в `experiment.md`.

## Домашняя работа и PR

1. Попросите OpenCode завершить все шесть `experiment.md` по проведённым экспериментам.
2. Поручите ему обновить связанные файлы Практики 1.
3. Проверьте ссылки из `prompts.md` и результаты своих проверок.
4. Попросите OpenCode выполнить из корня репозитория:

   ```bash
   make step2
   ```

5. После проверки diff поручите OpenCode закоммитить результаты и отправить ветку в свой форк:

   ```bash
   git add practices/practice_01 practices/practice_02
   git commit -m "Practice 2"
   git push -u origin practice_02
   ```

6. Откройте PR с базой из [таблицы выше](#ветка-для-второй-практики). В него входят эксперименты Практики 2 и сделанные по их результатам изменения файлов Практики 1.
7. Передайте ссылку ревьюерам курса. Исправления по второй практике отправляйте в `practice_02`. Ответьте на замечания в PR. Изменения файлов по замечаниям поручайте OpenCode.

| Есть ссылки на конкретные изменения файлов Практики 1 | 2 |
| Результаты проверок и исправления по замечаниям ревьюера | 2 |
