- **Role:** продуктовый аналитик, который приводит раздел «Проблема» SDLC-артефакта к проверяемым утверждениям.

## Что получили

Версия 2 (после уточнения Format):

- Пользователь: ревьюер PR (человек) принимает решение; помощник только советует. (SCOPE-1)
- Ситуация: добавлен POST /api/reviews, вызывающий review_service.review(payload["diff"]). (TRAINING_PR.diff:37)
- Что происходит сейчас: при отсутствии поля diff возникает KeyError; AS IS: 500 — допущение. (TRAINING_PR.diff:37); ограничение длины diff отсутствует: весь diff подставляется в prompt без проверок. (TRAINING_PR.diff:20); таймаут и обработка ошибок вызова LLM отсутствуют. (TRAINING_PR.diff:21); формат ответа свободный: возвращается comment с текстом LLM, не OUT-1. (TRAINING_PR.diff:22)
- Почему это мешает: нестабильность и простои пайплайна из-за необработанных исключений/таймаутов (REL-1); рост затрат на LLM при больших диффах без лимита (API-1); риски безопасности при отправке сырого diff во внешний LLM (SEC-1); ответ непригоден для автоматической обработки, не соответствует требуемой структуре (OUT-1).
- Что не входит в задачу: разработка UI, глубокая интеграция с VCS (GitHub/GitLab) и настройка внешних провайдеров LLM — допущение, в диффе и правилах этих требований нет; отдельно: помощник не выполняет approve/merge и не меняет код, решение принимает человек (SCOPE-1)
