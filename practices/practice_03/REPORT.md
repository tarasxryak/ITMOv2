# Практика 3: отчёт о локальном помощнике
## 1. Железо и версии
- Apple M3, 16 GB unified memory, macOS 26.6
- Ollama 0.35.1 (установка brew, сервис через brew services)
- OpenCode 1.18.33
- Python 3.14 (make test)
- Рабочий агент: OpenCode Build, vsellm/openai/gpt-5 (облако, только для подготовки файлов и эталонов; на вопросы отвечала только локальная модель)

## 2. Модель
- База: qwen3.5:4b (ID d8b0f5e9760c), 4.2B параметров, Q4_K_M, ~3.3 GB на диске, поддерживает tools и thinking
- Сборки:
  - itmo-chat из lab/Modelfile (num_ctx 4096; запуск прямого чата: `ollama run itmo-chat`) (thinking выключается флагом --think=false)
  - itmo-agent из lab/Modelfile.agent (num_ctx 65536; для OpenCode; `ollama ps`: ~4.5 GB, 100% GPU)
- Параметры: temperature 0.2, seed 42, num_predict 1024/4096

## 3. Обоснование выбора
- На 16 GB 4B в Q4 даёт запас под 64k контекста и системные процессы
- Умеет вызывать инструменты (иначе OpenCode-агент не прочитает файлы)
- Для read-only вопросов по маленькому репозиторию 4B достаточно
- Ранее стояла Qwen3.5-9B Q4_K_M через llama.cpp — удалена: тяжелее и не через Ollama (требование практики)

## 4. Настройка OpenCode (lab/demo/opencode.json)
- Провайдер: ollama, baseURL http://localhost:11434/v1
- Агент local-guide: "*": deny; разрешены только read/glob/grep/list; явные deny на edit/bash/webfetch/external_directory
- steps: 8; temperature: 0.2; options.reasoningEffort: none

## 5. Проблемы и как решены
- (а) Границы проекта: внутри git-репозитория OpenCode считает весь репозиторий проектом; `external_directory: deny` не помешал local-guide прочитать `../REFERENCE.md` (проверено). Решение: `lab/ask.sh` запускает каждый вопрос в новой сессии на временной копии demo вне репозитория; там чтение снаружи блокируется (проверено: «rule which prevents you from using this specific tool call»).
- (б) Режим thinking по умолчанию: простой запуск шёл ~4.5–5 мин; `reasoningEffort: none` сократил до 16 с на пробном вопросе и 28–47 с на каждый из пяти вопросов (с учётом запуска рабочего агента); цена — модель меньше рассуждает.
- (в) Первая версия `ask.sh` писала ответ во временный каталог и теряла его — исправлено (формирование абсолютного `OUTFILE` до `cd` и запись через `tee`).

## 7. Ограничения и выводы
- 4B слабо держит формат «факт + файл:строка» из repo-system.txt
- Встречаются утечки токенов другого языка
- В q1 ссылка содержит абсолютный путь временного каталога
- Изоляцию чтения нельзя доверять одним permission внутри репозитория
- Без thinking ответы быстрые и на этой задаче без галлюцинаций
- (а) Ложноотрицательный ответ на случайном вопросе вне пяти проверок («Что возвращает subscribe при успешной подписке?»): модель искала глобом только `**/*.{js,ts,json,xml,yaml,yml,text}`, не нашла service.py и ответила, что информации нет (эталон: `{"subscribed": True}`, lab/demo/service.py:8). Возможное улучшение — потребовать в `repo-system.txt` начинать с glob `**/*` без фильтра по расширениям; в этой работе не применялось, чтобы пять ответов остались получены на одной конфигурации.
- (б) Прямой чат itmo-chat без файлов галлюцинирует детали: на вопрос о хранении подписчиков в памяти упомянул std::vector/std::map, хотя проект на Python; SYSTEM в Modelfile от этого не защищает.

## 8. Как воспроизвести и демо

```bash
make test
(cd lab && ollama create itmo-chat -f Modelfile && ollama create itmo-agent -f Modelfile.agent)
./lab/ask.sh "вопрос" [файл]
ollama run itmo-chat --think=false
```

Без `--think=false` itmo-chat тратит весь `num_predict` 1024 на размышления и обрывается, не дав ответа (проверено).
