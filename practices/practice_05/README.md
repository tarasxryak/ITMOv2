# Домашнее задание № 5 — Spec-Driven Development

Задание курса: реализовать следующую User Story сквозного проекта с учётом новых правил и Spec-Driven Development.

Продолжение **Looksmax Grocery** из практики 4 — фича «Ачивки». Исходные спецификации и согласованный контракт уже находились в рабочем дереве; реализация завершает эту заготовку, без переноса и дублирования приложения.

## Артефакты

Пути относительно `practices/practice_04/looksmax/`:

- `AGENTS.md`, `.specify/memory/constitution.md` — правила работы и конституция.
- `specs/contracts/achievements.md` — согласованный контракт v1.0.
- `specs/001-achievements-logic/` — спецификация, план, модель данных и задачи логики.
- `specs/002-achievements-ui/` — спецификация, план, сценарии приёмки и задачи интерфейса.
- `docs/evidence/achievements-ui.md` — результат реализации, проверки и ограничения среды.

Правила и контракт не переписывались под реализацию. Новые функции и исправления логики разрабатывались через падающие тесты, затем минимальную реализацию и полный прогон тестов фронтенда.

## Результат

19 достижений для дуэли, корзины, кликера и магазина тем. Общий баланс получает награду ровно один раз. Список показывает прогресс, группы, даты открытий и новые достижения. Уведомления объединяют несколько открытий, учитывают скрытую вкладку и старый профиль; итоги игр показывают открытия своей партии. Повреждённые данные браузера исправляются при загрузке.

## Запуск и проверка

Из корня репозитория:

```sh
make step5
make -C practices/practice_05 run
```

`run` собирает фронтенд и запускает сервис на http://127.0.0.1:8765. Зависимости устанавливаются по README приложения.

## Демонстрация на сдаче

1. Открыть приложение, нажать кубок в шапке: 19 карточек, 0 открытых; «Коллекционер» — «2 из 4».
2. Сдать корзину: уведомление «Первая корзина», +20 к общему балансу и блок «Открыто за игру» в итоге.
3. Открыть список: карточка отмечена «новая». Закрыть окно: метка новых исчезает.
4. Перезагрузить страницу: достижение и баланс сохранены, повторной награды нет.
5. Пройти дуэль до итога; показать достижения кликера и тем. Для пограничных состояний и фоновых открытий — сценарии в `specs/002-achievements-ui/quickstart.md`.

В среде агента проверка типов и 292 теста фронтенда прошли, production-сборка успешна. Полный `check.sh` и браузерная приёмка не завершены: песочница запрещает открывать локальные порты и запускать Chrome. Перед сдачей необходимо выполнить полную команду проверки и браузерные сценарии вне этих ограничений; скриншоты новой реализации не заявляются готовыми.

## PR и CI

Сдача подготовлена отдельной веткой `practice_05` поверх `practice_04`: ДЗ № 4 пока находится в открытом PR #4. После его слияния базу PR ДЗ № 5 можно переключить на `main`. Изменения материалов курса из `main` и посторонние локальные файлы в сдачу не включаются.

Workflow `.github/workflows/homework-05.yml` запускает неизменённый `scripts/check.sh`, production-сборку и `tools/achievements-smoke.mjs` в настоящем Chrome. Браузерный прогон проверяет тысячный клик, награду 101, просмотр, сохранение и отсутствие повторной награды после перезагрузки, а также 19 карточек на ширинах 320 и 1280 во всех четырёх темах. Ошибка JS-шага или горизонтальная прокрутка делают проверку красной. Скриншоты и логи доступны как артефакт `homework-05-browser-evidence` в GitHub Actions. Этот smoke-прогон не заменяет ручную проверку Safari/VoiceOver.
