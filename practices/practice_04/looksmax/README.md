# Looksmax Grocery

Три игры на продуктах ВкусВилла и общей валюте. Данные о товарах, цены и КБЖУ берутся из MCP ВкусВилла.

- **Дуэль.** 10 раундов, в каждом три случайных продукта из всего каталога. Выбери тот, где больше белка на калорию (скор = белки × 4 / ккал). Криптошекели за верные ответы, подсказка, ранг от sub3 до true adam, корзина ВкусВилла из выбранного.
- **Кликер.** Клик по монете и автокликеры дают криптошекели в секунду. Ими покупаются улучшения и темы сайта: Сакура с падающими лепестками и неоновый Cyberpunk. Криптошекели общие для всех игр.
- **Корзина на бюджет.** 12 случайных продуктов и бюджет. Набери корзину с максимумом белка: каждый товар один раз, не больше 2 из одной категории, не больше 2000 ккал. В конце игра показывает самую эффективную корзину за эти деньги.

Правила и формулы: [`docs/requirements.md`](docs/requirements.md).

## Запуск

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
npm --prefix web ci
npm --prefix web run build
.venv/bin/python serve.py          # http://127.0.0.1:8765
```

`serve.py` раздаёт собранный фронтенд и принимает `POST /api/cart`: браузер не может звать MCP ВкусВилла напрямую. Для разработки фронтенда: `npm --prefix web run dev` (запросы `/api` уходят на `serve.py`). Адрес с `?seed=7` делает раунды воспроизводимыми.

## Каталог товаров

Игры берут товары из `web/public/catalog.json`. В репозитории лежит стартовый набор из 46 реальных товаров из сохранённых ответов MCP ВкусВилла. У MCP нет выгрузки всего ассортимента, поэтому полный каталог собирается поиском по 190 запросам из всех отделов:

```sh
.venv/bin/python scripts/build_catalog.py            # нужен доступ к https://mcp.vkusvill.ru
.venv/bin/python scripts/build_catalog.py --no-details   # быстрее, но без граммовки из product_details
```

Скрипт не записывает каталог, который не годится для игр (мало товаров, неверный скор, нет категорий).

## Проверки

```sh
sh scripts/check.sh    # тесты Python, типы и тесты фронтенда
```

## Среда агента

`AGENTS.md` (правила), skills `test-driven-development` и `frontend-design`, MCP `vkusvill` (данные), `looksmax` (свои tools), `shadcn` (компоненты интерфейса), hook, который запускает `scripts/check.sh` после каждой правки. Компоненты shadcn получены через MCP shadcn: журнал вызовов в `docs/evidence/shadcn-mcp.json`, повторить можно `tools/shadcn_fetch.py`.
